# Path Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un hub en español donde estudiantes exploran equipos, proyectos y personas, y cada ficha lleva un README seguro y un enlace externo, desplegado en `*.workers.dev`.

**Architecture:** Astro SSR con el adaptador de Cloudflare, un solo Worker, D1 como base de datos. Un esqueleto con el contrato de datos (Task 1) se fija primero; después tres agentes trabajan en paralelo en carpetas separadas (Tasks 2, 3, 4) y Task 5 integra y despliega.

**Tech Stack:** Astro 5 + `@astrojs/cloudflare`, TypeScript, D1, `arctic` (OAuth Google y GitHub), `markdown-it`, `sanitize-html`, Vitest, wrangler 4.

**Spec:** `docs/superpowers/specs/2026-11-16-path-hub-design.md`

## Global Constraints

- Interfaz en español, tuteo, frases en minúscula salvo el inicio (tono cálido, como Invivo Lab, sin copiar su estructura).
- Node 22, npm 10, wrangler 4.163 ya autenticado; despliegue en `workers.dev`.
- README: Markdown sin HTML crudo y sin imágenes; stickers solo del set fijo con la sintaxis `:nombre:`; máximo 20 000 caracteres.
- Enlaces externos: solo `https:`; en el README llevan `rel="nofollow ugc noopener"`.
- Fichas con estado `hidden` nunca aparecen en listados ni en su URL (404).
- Fichas curadas muestran `verificado_en`; los datos sin confirmar llevan la marca "por confirmar". Sin contenido sensible de defensa o UAV.
- Dirección visual en `DESIGN.md` (formato design.md) y validada con `npx @google/design.md lint DESIGN.md`. No copiar fuentes ni estructura de Invivo Lab.
- Cada tarea termina con commit en `main` de `Marquinhos9873/path-collaborative-projects`.

## Review Focus

1. README con `<script>`, `<img>`, `[x](javascript:alert(1))`, `![img](https://x/y.png)` y `<a onclick>`: debe salir inerte (sin script, sin imagen, sin enlace peligroso). Cubierto en Task 4.
2. Filtros sin resultados o con parámetros inválidos en la URL (`?pais=zz&nivel=<x>`): lista vacía con mensaje que invita a actuar, nunca error 500. Task 3.
3. Dos equipos con el mismo nombre: el `slug` se resuelve con sufijo (`-2`), sin sobrescribir. Task 1.
4. Un usuario edita o borra la ficha de otro (equipo ajeno por ID): responde 403. Task 3.
5. Falta el binding D1 o los secretos OAuth en local o en el primer despliegue: el sitio carga y el login muestra "inicio de sesión no disponible", no un error. Task 1.
